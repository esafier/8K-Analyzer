# Data hunter

A method for finding data that isn't sitting in a press release. The core insight: **"not published" and "not observable" are different things.** Most operational data (trades, listings, prices, filings, registrations, schedules) is generated by a system that exposes it through an API feeding its own UI — even when nobody has written an article about it. The failure mode this skill prevents is searching for *articles about the data*, finding none, and concluding the data doesn't exist.

## Before starting: frame the target

Write down (mentally or literally) before any tool call:

1. **The exact metric**: what quantity, at what grain (per-instrument? daily? monthly?), over what window.
2. **Who generates it**: which system of record produces this data as a side effect of operating? (An exchange generates volume. A registry generates filings. A retailer generates prices and stock states.)
3. **What would count as done**: an approximation reconstructed from primitives often satisfies the real need. Decide up front what precision is required.

## The escalation ladder

Work down the rungs in order. Time-box each rung to a few minutes of effort; do not stop at a failed rung — a failure is the signal to descend, not to report back. Only report back when the ladder is exhausted or the data is in hand.

### Rung 1 — Published sources (the fast path)
Web search for the data itself, official disclosures (IR pages, filings, press releases), and known aggregators. Also search for `<entity> API`, `<entity> developer docs`, `<entity> data download` — the docs are often the fastest route to Rung 2. If this yields the data, done. If it yields only *commentary* ("company X does not break out metric Y"), treat that as a claim about *publication*, not availability, and descend.

### Rung 2 — The system of record's own API
The platform that executes/registers/serves the thing has machine-readable endpoints. In order:

1. **Official API docs** (often at `/api`, `developers.`, `docs.` subdomains).
2. **Standard path conventions** — probe with curl from the sandbox. REST APIs are boringly conventional: `/api/v1/`, `/api/v2/`, resources named in the obvious plural (`/markets/`, `/products/`, `/instruments/`, `/tickers/`, `/stats/`).
3. **Naming-scheme inference** — if the entity has a known product family, guess sibling symbols. (A spot pair `btcusd` implies a derivative might live at `btcusd-perp`, `btc-usd-swap`, `BTCUSDT`, etc. Try 3–4 conventions.)
4. **Enumerate before drilling.** Find the *listing* endpoint first (all markets / all products / all filings). It tells you the exact identifiers, the full universe, and often reveals fields nobody documents. Then hit the per-item endpoint.
5. **Read every field in the JSON.** Responses routinely carry more than the UI shows — open interest inside a price ticker, timestamps that reveal launch dates, internal IDs that unlock other endpoints.

### Rung 3 — Browser network reconnaissance
If the site renders data in JavaScript or the API isn't guessable: open the page with browser tools, and read the network requests the page itself makes (`read_network_requests` in Claude-in-Chrome, or the page's JS bundle for endpoint strings). Whatever XHR/fetch call populates the chart on screen is a public endpoint you can replay with curl — usually with better parameters (longer ranges, higher limits) than the UI exposes. Bot-walls (Incapsula, Cloudflare) on HTML pages frequently do NOT protect the JSON API paths — a blocked webpage does not mean a blocked API. Test them separately.

### Rung 4 — Third-party APIs and datasets
Aggregators, official statistics portals, and archives with machine access. See `references/probing-patterns.md` for the domain-by-domain list (financial, government, web-archive). Two that are chronically underused:
- **Wayback Machine / archive.org** — historical snapshots of pages reconstruct time series that were only ever shown as "current" numbers (follower counts, prices, stated metrics on IR pages).
- **CDX API + sitemap.xml** — enumerate what pages/documents an entity has ever published.

### Rung 5 — Reconstruction from primitives
When the target metric is not stored anywhere, derive it:
- **Notional = base volume × price** (per candle, using OHLC average or VWAP).
- **Launch/start dates = first record** in a history endpoint.
- **Growth series = diffs of archived snapshots** of a "current total" figure.
- **Shares/mix = your series ÷ an officially disclosed aggregate.**
State the derivation method explicitly in the output — a reconstructed number with stated methodology beats a shrug.

### Rung 6 — Structured handoff to the user
Only when the remaining barrier is genuine authentication, a paywall, or an interactive session. Do not ask the user vaguely to "check the site." Give them: the exact URL, the exact click path, the exact export button or copy target, and the format to paste back. One trip, everything needed.

## Behavioral norms (these are the actual skill)

- **A dead end is a fork, not a wall.** Each failed probe narrows the search. `{"message": "Not found."}` on `/api/v2/derivatives/` means the API root is live and speaking JSON — keep guessing paths. A 403 on HTML but 200 on JSON means bot-wall on pages only.
- **Use the sandbox, not just search tools.** curl from bash is the primary probing instrument: it shows raw responses, headers, and errors that search snippets never will. Write small Python loops to enumerate, paginate, and pull full histories once an endpoint works.
- **Cross-check before trusting.** Reconcile at least one number from the scraped series against an officially disclosed figure (a quarterly total, a reported ADV). If it can't be reconciled, say so and explain the wedge (netting basis, scope, single-counting vs double-counting).
- **Preserve provenance.** Save raw pulls to CSV with the source endpoint, pull timestamp, and derivation method. Data without provenance is unusable in serious work.
- **Flag point-in-time-only metrics.** Some values (open interest, current inventory, live counts) have no history endpoint. Snapshot them, label the snapshot date, and offer to set up forward sampling rather than pretending history exists.
- **Precise failure vocabulary.** Never say "the data isn't available." Say which it is: *not published* (but observable — keep going), *behind authentication* (hand off), *not stored anywhere* (only claimable after Rungs 1–5), or *only observable going forward* (start sampling).
- **Politeness and legality.** Throttle requests (sleep between calls). Stop at real authentication — never enter, guess, or ask for credentials; never bypass CAPTCHAs or paywalls; respect explicit API terms. Public unauthenticated endpoints that a site's own frontend calls are fair game; account-gated ones are the user's to access via Rung 6.

## Output format

Deliver three things:
1. **The data** — CSV file(s) with provenance columns, plus a chart when the series has a shape worth seeing.
2. **The method** — one short paragraph: which rung worked, which endpoints, what was derived vs. raw.
3. **The gaps** — what remains unobtainable and its precise failure category, plus the forward plan (sampling, handoff, or nothing).

## Worked example (compressed)

Target: historical volumes for an exchange's perp contracts; no public disclosure exists.
- Rung 1: searches return only "company does not break out perp volume." Descend.
- Rung 2: spot API known at `/api/v2/`. Probe `/api/v2/markets/` → 319 markets, 20 flagged `market_type: PERPETUAL` (enumeration first). Guess `ticker/btcusd-perp/` → works, and the JSON carries `open_interest` fields the docs never mention (read every field). `ohlc/{sym}/?step=86400&limit=1000` → daily candles back to first trade.
- Rung 5: notional = volume × OHLC average; launch dates = first candles; perp share = series ÷ officially reported venue total (cross-check: 21% — plausible).
- Flag: OI has no history endpoint → snapshot dated, forward sampling offered.
Total: full multi-year daily dataset from a "no data available" starting point, in ~six tool calls.

For domain-specific endpoint conventions and source lists, read `references/probing-patterns.md`.
